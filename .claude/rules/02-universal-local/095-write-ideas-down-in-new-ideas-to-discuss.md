# Write ideas down in `dev_docs/new_ideas_to_discuss.md` when they occur

Whenever an idea worth discussing occurs to you, write it down in `dev_docs/new_ideas_to_discuss.md` at once, in the
format the file describes, unless a tagged code comment holds it better (one about a piece of code: see the rule on
tagged todo comments). Ideas that come up while working on something else, or that are about no one piece of code, go
there. Mentioning an idea only in a response isn't enough: Magnus can miss it, and it's gone once the conversation is.

Magnus, 2026-11-11: "You can add stuff there too when you come up with ideas if code comments don't fit. We don't want
great ideas lost because I missed something you wrote in a response somewhere, or you had nowhere to note them down when
they occurred to you when working on something else...."

- **Magnus adds his there too,** and the file is where the two of you work off of: read it when starting work that an
  idea there may bear on.
- **An idea discussed moves to the document it belongs in,** with attribution, or is dropped, and goes from the file.
  Keep the file itself, even when it's empty.
- **Say in your response that you added an idea there,** in a line, so Magnus knows to look.
