# Repository structure

## .NET — projects under `src/src_dotnet/`, solution `JAStudio.slnx` at the repo root

- `JAStudio.UI/` — Avalonia UI (Views in `.axaml`, ViewModels in `.cs`)
- `JAStudio.StandaloneHost/` — the standalone JAStudio: JAStudio with its workspace window, as inside Anki, with Anki
  entirely out of the loop, started on a checkout's add-on folder (see `dev_docs/standalone-jastudio.md`)
- `JAStudio.HeadlessHost/` — the headless JAStudio: JAStudio without Anki or a screen, serving JAStudio's MCP server
  (see `dev_docs/jastudio-mcp.md`)
- `JAStudio.Core/` — pure domain logic; no UI / Anki / Python dependencies
- `JAStudio.PythonInterop/` — the only layer allowed to bridge C# ↔ Python (pythonnet)
- `JAStudio.Anki/` — C#-side Anki integration utilities (no direct pythonnet — that belongs in PythonInterop)
- `JAStudio.Web/` — in-process Kestrel/Blazor card-rendering server (see `dev_docs/web-rendering-architecture.md`)
- `JAStudio.Dictionary/` — Japanese dictionary integration
- `JAStudio.TextToSpeech/` — JAStudio's own TTS: the tts-providers (Azure, Google), voices and settings (see
  `dev_docs/text-to-speech.md`)
- `JAStudio.Audio/` — decoding, comparing and playing audio, with SoundFlow, for the UI
- `Mp3LoudnessNormalization/` — brings MP3 files to ReplayGain's reference loudness as mp3gain does, byte for byte;
  knows nothing of JAStudio (see `dev_docs/mp3-loudness-normalization.md`)
- `*.Specifications/` projects (`JAStudio.Core.Specifications/`, `JAStudio.UI.Specifications/`,
  `JAStudio.Web.Specifications/`, …) — xUnit v3 black-box specs
- `JAStudio.UI.Views.Specifications/` — specs that open the windows themselves, on Avalonia's headless platform
  (`SpecificationOpeningWindows`). Each window a spec renders lands in `RenderedWindows/<name>.png` in its output folder:
  render a window you built and read the image to see it. A process of its own, since the headless platform takes over
  the UI dispatcher that `JAStudio.UI.Specifications` relies on.

## Python

- Source: `src/jastudio_src/`, `src/jaslib_src/`, `src/jaspythonutils_src/`
- Tests: `src/tests/{jastudio_tests,jaslib_tests,jaspythonutils_tests}/`

## Generated / third-party / off-limits — do not hand-edit

- `typings/` — auto-generated by `regenerate-stubs.ps1`
- `src/runtime_binaries/` — copied .NET output; the addon refreshes it from the newest `bin/` build on every
  Anki startup (`jastudio/dotnet/copy_runtime_binaries.py`), so a rebuild reaches Anki on its next restart
- `src/jastudio_src/_lib/`, `_lib_patched/`, `manually_copied_in_libraries/` — bundled third-party Python
  libs, excluded from lint/typecheck
- `submodules/pythonnet-stub-generator` — read-only third-party code, a separate repo excluded from
  lint/typecheck/search; coordinate changes through its own workflow
- `src/jas_database` — **the corpus repository** (`JAStudioData`), a submodule: the corpus notes, the import profiles and
  the media layer, itself with the media submodules `media/commercial-01` and `media/commercial-02`. Excluded from
  lint/typecheck/search. It's JAStudio's own data, which the code reads and writes, not third-party code. Change it only
  as part of work that changes what the code expects of it, and commit it with that work: see
  [045-committing-with-the-corpus-repository.md](045-committing-with-the-corpus-repository.md)
- `.github/workflows/` — CI configuration; don't modify without explicit permission
- Build artifacts: `bin/`, `obj/`, `venv/`, `.vs/`, `CopilotIndices/`
